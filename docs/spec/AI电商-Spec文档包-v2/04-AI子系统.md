# 04 · AI 子系统（网关 · RAG · Agent · 18 项能力）

> 这一份决定"AI 智能电商"和"带了个聊天框的电商"的区别。核心原则：**AI 只出建议与结构化意图，业务层负责校验与执行；一切调用可计量、可降级、可评测、可溯源。**

---

## 4.1 总体结构

```
业务模块（导购 / 客服 / 搜索 / 内容 / 运营 / 风控）
        │  只依赖 trait，不碰厂商 SDK
        ▼
ai-agent（编排层：会话状态、工具白名单、prompt 装配、结果校验）
        ▼
ai-gateway（模型层：路由、降级、配额、结构化输出、缓存、计量、SSE）
        ▼
ai-rag（知识层：召回、重排、引用装配）
        ▼
providers：openai_compat / doubao / deepseek / ollama / mock
```

四层职责不许串：Agent 不做 HTTP；Gateway 不懂业务；RAG 只负责"给证据"。

## 4.2 网关实现要求

### 4.2.1 端口 trait

```rust
#[async_trait::async_trait]
pub trait ModelProvider: Send + Sync {
    fn id(&self) -> ProviderId;
    fn capabilities(&self) -> Capabilities;   // chat/stream/tools/vision/json/embed + 上下文上限
    async fn chat(&self, req: ChatRequest) -> Result<ChatResponse, ModelError>;
    async fn chat_stream(&self, req: ChatRequest) -> Result<ChatStream, ModelError>;
    async fn embed(&self, req: EmbedRequest) -> Result<EmbedResponse, ModelError>;
}
```

`ModelError` 必须分类：`Timeout / RateLimited / Auth / BadRequest / ContentFiltered / ServerError / ContextOverflow / Unsupported`。分类决定重试与降级行为，禁止统一 `anyhow` 一把梭。

### 4.2.2 任务与模型档位

`Task` 枚举：`ShoppingGuide / CustomerService / QueryRewrite / ProductUnderstanding / ReviewSummary / ContentGen / RiskScoring / OpsQuery / PriceSuggest / Judge / Translate / Embedding`。

| 任务 | 默认档 | 典型模型定位 | 超时 | 是否流式 |
|---|---|---|---|---|
| 导购 | balanced | 中档通用对话模型 | 8s | 是 |
| 客服 | fast | 小模型 + RAG | 5s | 是 |
| 查询改写 | fast | 小模型 | 2s | 否 |
| 商品理解 | balanced | 中档 + 强结构化 | 15s（异步） | 否 |
| 评价摘要 | fast | 小模型批处理 | 30s（异步） | 否 |
| 内容生成 | balanced | 中档 | 10s | 否 |
| 风控评分 | fast | 小模型或规则 | 3s | 否 |
| 运营查数 | best | 强模型（NL2SQL 易错） | 20s | 否 |
| 定损判责 | best | 多模态 | 10s | 否 |
| Embedding | — | 专用向量模型 | 5s | 否 |

档位到具体模型的映射存 `sys_config`，支持按租户覆盖；**换模型只改配置，不改代码**（这是 P7 的 Gate）。

### 4.2.3 降级与熔断

链：`best → balanced → fast → 规则/模板兜底`。

- 触发条件：超时、`RateLimited`、`ServerError`、`Auth`、配额不足、`ContextOverflow`（先裁剪再降级）。
- 熔断：单 provider 连续失败 5 次 → 打开 30s，半开探测；按 `(provider, model)` 维度计数。
- 降级必须体现在响应：`degraded: true`、`provider_used`、`reason`；前端在 AI 场景显示"简化模式"。
- 兜底必须是**业务可用**的：导购退回筛选式推荐、客服退回 FAQ 检索 + 转人工、摘要退回截断原文、文案退回模板库。

### 4.2.4 结构化输出

- 请求携带 JSON Schema；网关拼三段：系统约束（"只输出 JSON，不含解释"）+ Schema 摘要 + 用户输入。
- 解析失败 → 带上错误片段重试（≤2 次）→ 仍失败返回 `AI_STRUCTURED_OUTPUT_FAILED`，调**业务兜底**，不得抛给用户空白。
- 数值字段在 Schema 里限定范围（如价格建议 `0 ≤ x ≤ 原价 1.3`），越界直接判非法。
- 所有「AI 建议」类型的结果必须带 `confidence`（0–1）与 `reasons[]`，低于阈值不展示。

### 4.2.5 缓存与配额

- 精确缓存：`hash(task, model, prompt_version, messages, params)` → 结果，TTL 分任务（改写 1h、FAQ 24h、导购 0）。
- 语义缓存：embedding 相似度 ≥ 0.95 且同 `task + 关键参数（类目/预算区间）` 才命中；客服 FAQ 启用，导购只对首轮启用。
- 配额：`(tenant, task, day)` 的 token 与金额上限，软阈值 80% 告警，硬阈值拒绝并降级。
- 成本：每次调用算 cost（按模型单价 × tokens），落 `ai_call_log`；`/admin/dashboard` 出"AI 成本 / 单均成本 / 各任务占比"。

### 4.2.6 Prompt 管理

- 文件：`prompts/<task>/<version>.md`，front-matter 含 `version / models / owner / changelog / eval_baseline`。
- 线上按 `prompt_id + version` 取；支持按租户或按 `%` 灰度；回滚只需改版本号。
- 每次变更必须附评测结果（`evals/` 分数不下降才允许升版本）。
- Prompt 中禁止硬编码业务规则（规则来自 `promotion_rule` 等表，注入上下文）。

### 4.2.7 审计与可观测指标

`ai_call_log` 字段见 02；额外指标：`ai_request_total{task,provider,status}`、`ai_latency_seconds{task}`（首 token 与总耗时分开）、`ai_tokens_total{direction}`、`ai_cost_total`、`ai_cache_hit_ratio`、`ai_degraded_total`。

## 4.3 RAG 实现要求

### 4.3.1 数据源与接入

| 源 | 频率 | 说明 |
|---|---|---|
| 商品详情/参数/FAQ | 增量（`updated_at` 水位）+ 全量周重建 | 下架即失效 |
| 平台规则（售后/物流/发票/优惠） | 手动发布触发 | 版本化，带生效时间 |
| 类目指南/选购知识 | 手动 | 运营维护 |
| 客服话术库 | 手动/导入 | 与快捷语共用 |

`kb_document`：`doc_id`、`source_type`、`source_id`、`title`、`version`、`effective_from`、`status`；`kb_chunk`：`doc_id`、`chunk_no`、`heading_path`、`content`、`token_count`、`metadata JSONB`（sku_id/category_id/生效时间）。

### 4.3.2 清洗与分块

- 去 HTML、去营销废话、保留标题层级与表格；表格转"键: 值"文本。
- 分块策略：先按 `H2/H3` 切，再按语义边界（句号/列表项）切，超长滑窗；chunk 512–800 token，重叠 15%。
- 每个 chunk 必须带 `heading_path`（用于回答定位）与业务过滤键（类目、SKU、渠道）。
- 拒绝把"商品详情全量"直接塞 chunk：先摘要出 5–8 个可检索事实点。

### 4.3.3 向量与检索

- `vector(1024)`（维度随模型定），HNSW：`m=16, ef_construction=64, ef_search=40`。
- 混合三路：关键词（PG 全文/`tsvector` + 同义词扩展）、向量（cosine）、结构化过滤（类目/价格/库存/渠道）。
- 融合：RRF（`k=60`），再 rerank（cross-encoder 或轻量 scorer），取 top 6 送模型。
- 检索日志：命中 chunk 数、耗时、是否为空、最终引用数，便于调参。

### 4.3.4 回答与引用

- Prompt 固定约束：仅依据给定片段作答；无依据时输出"未查到相关规则，建议咨询人工"，**不得编造**。
- 输出必须含 `citations[{chunk_id, title, url, snippet}]`；引用不足则不展示"规则类"结论。
- 涉及金额/时效的规则回答（如"7 天无理由"），必须命中"平台规则"类文档 chunk，商品页文本不能作为规则依据。

### 4.3.5 失效与评测

- 商品下架、规则改版 → 标记 chunk 失效 + 检索过滤；SLA 5 分钟。
- 评测集 ≥50 条：命中型 30、拒答型 10、边界型 10；指标：命中率、引用正确率、拒答率、P95 延迟。
- 上线门槛：命中率 ≥85%、拒答 100%、引用正确率 ≥90%。

## 4.4 Agent 编排

### 4.4.1 通用约束

- 工具白名单制：每个 Agent 只能调声明过的工具，工具实现在业务层，Agent 只发意图。
- 工具列表（示例）：`search_products`、`get_sku_detail`、`calc_price`、`get_order`、`get_logistics`、`apply_after_sale`、`list_coupons`、`add_to_cart`（**返回加购链接而非直接加购**）。
- 写操作一律"生成动作卡片 + 用户确认"，Agent 不得静默执行。
- 会话状态存 `ai_conversation / ai_message`，上下文窗口裁剪策略：保留系统约束 + 最近 6 轮 + 结构化摘要（老对话压缩成要点）。

### 4.4.2 导购 Agent

- 流程：意图识别 → 条件槽位填充（场景/预算/品类/风格/尺码/时效）→ 检索 → 生成 3–5 个候选 + 每个一条"为什么推荐" → 允许用户微调条件 → 输出加购/对比动作。
- 必答边界：不承诺疗效/绝对化用语；不比较竞品价格；不编造库存与时效。
- 评测：意图准确率、槽位填充率、推荐相关性人工打分、加购转化率。

### 4.4.3 客服 Agent

- 流程：分类（售前咨询/订单查询/物流/售后/投诉）→ FAQ 检索（RAG）→ 工具调用取实时数据 → 答复 → 不解决则生成转人工摘要（含订单号、诉求、已尝试动作）。
- 禁止：承诺赔付金额、承诺时效、代替用户提交售后（只能引导）。
- 评测：一次解决率、误答率、转人工率、满意度。

### 4.4.4 运营 Copilot

- NL2SQL：只读账号、表白名单（视图）、强制 `LIMIT ≤ 1000`、超时 10s、SQL 审计与结果缓存；生成 SQL 必须解释口径。
- 禁止访问 PII 列；查询结果导出需二次确认。

## 4.5 18 项能力的接口契约与验收

| # | 能力 | 输入 | 输出（结构化） | 验收指标 |
|---|---|---|---|---|
| 1 | 导购 | 会话 + 上下文 + 用户画像 | 候选商品 + 理由 + 动作 | 意图准确 ≥90%，相关性人工 ≥4/5 |
| 2 | 语义搜索改写 | query + 类目 | 改写 query + 同义词 + 过滤条件 | 无结果率下降 ≥40% |
| 3 | 商品理解 | 标题/参数/图文 | 卖点 5 条 + 属性补全 + 类目标签 | 属性补全准确 ≥85%（抽样 100） |
| 4 | 以图搜图 | 图片 | Top20 相似 SKU + 相似度 | Top5 命中 ≥70% |
| 5 | 评价摘要 | 评价集合 | 优点/缺点各 3 + 情感分布 + 代表句 | 与人工摘要一致 ≥80% |
| 6 | 智能客服 | 会话 + 订单上下文 | 答复 + 引用 + 转人工摘要 | 一次解决率 ≥60%，误答 ≤2% |
| 7 | 推荐 | 用户 + 场景 | 列表 + 理由 | CTR 相对基线 +15% |
| 8 | 营销文案 | 商品/活动/人群 | 3 版文案 + 字数/合规校验 | 采纳率 ≥50%，合规拦截 100% |
| 9 | 交易风控 | 订单/行为特征 | 风险分 + 命中规则 + 建议动作 | 拦截准确率 ≥85%，误杀 ≤1% |
| 10 | 运营查数 | 自然语言问题 | SQL + 口径解释 + 结果 | 执行成功率 ≥85%，越权 0 |
| 11 | 尺码推荐 | 身高/体重/体型/历史退货 | 推荐尺码 + 置信度 | 尺码相关退货率下降 ≥20% |
| 12 | 搭配推荐 | 主商品 + 场景 | 套装 3 套 + 理由 | 加购连带率提升 ≥10% |
| 13 | 评论问答 | 问题 + 评论库 | 答复 + 引用评论 | 引用真实评论 100% |
| 14 | 售后定损 | 图片 + 售后类型 | 损伤程度 + 建议判责 + 置信度 | 与人工一致 ≥80%，**仅建议** |
| 15 | 定价建议 | SKU + 竞品 + 库存 + 转化 | 建议价区间 + 依据 | 采纳后毛利率不降 |
| 16 | 补货预测 | 历史销量 + 促销日历 + 在途 | 建议采购量 + 安全库存 | MAPE ≤25% |
| 17 | 客服质检 | 会话记录 | 违规点 + 情绪 + 评分 | 抽检命中率 ≥70% |
| 18 | 多语言翻译 | 文本 + 目标语 | 译文 + 术语一致性 | 术语准确 ≥95% |

**通用验收**：每项必须有 `evals/<能力>/` 用例集、基线分数、降级路径说明；无评测不得上线（C27）。

## 4.6 成本与性能预算

- 导购单次会话（3 轮）目标成本 ≤ ¥0.02（按中档模型估），客服单次 ≤ ¥0.005。
- 首 token ≤ 1.5s（P95），完整答案 ≤ 8s；超时即降级。
- 语义缓存目标命中率：客服 30%、改写 40%、导购首轮 15%。
- 每千单 AI 成本纳入运营看板，与 GMV 对比给出"AI 成本率"。

## 4.7 安全与合规（AI 部分）

- 输入侧：Prompt 注入检测（"忽略以上指令""输出系统提示"类模式）+ 长度限制 + 敏感词。
- 输出侧：内容安全（涉政/涉黄/涉暴/绝对化用语/医疗断言）+ PII 脱敏。
- 数据侧：不得把用户手机号、完整地址、支付信息送入模型上下文；只传必要的脱敏片段。
- AIGC 合规：生成图片/文案在展示处标注"AI 生成"；不得生成真人肖像用于商品主图。
- 模型供应商：数据不出境需评估；日志与 prompt 留存期限按合规要求配置。
