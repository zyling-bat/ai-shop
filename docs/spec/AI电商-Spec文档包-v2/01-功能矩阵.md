# 01 · 功能矩阵（全量拉满版）

> 分三级：**M0 = 首版必须**（缺了不能上线）；**M1 = 二期**（首个版本后 1–2 个迭代）；**M2 = 增强**（有资源再做，代码里留开关）。
> `flag.*` 是功能开关键名，落 `feature_flag` 表，支持全局/用户级/店铺级三档灰度。

---

## 1.1 账号与身份

- M0 `flag.auth.sms` 手机号验证码注册/登录（验证码频控、图形码兜底）
- M0 `flag.auth.pwd` 账号密码登录（argon2id，失败锁定）
- M0 `flag.auth.oauth.wechat` 微信登录（公众号/开放平台），`flag.auth.oauth.apple` Apple 登录（iOS 必需）
- M0 `flag.auth.refresh` 短期 access + refresh 轮换，旧 token 立即失效
- M0 `flag.auth.device` 设备管理：设备列表、踢下线、常用设备标记
- M0 `flag.auth.logout` 注销：冷却期、数据删除与留存合规
- M1 `flag.auth.realname` 实名认证（个人三要素、企业四要素），敏感字段加密
- M1 `flag.auth.risk` 登录风控：异地提醒、异常设备验证、撞库防护
- M1 `flag.auth.minor` 未成年人模式、青少年内容过滤
- M1 `flag.auth.merge` 账号合并（同手机号多渠道）
- M2 `flag.auth.passkey` Passkey/WebAuthn
- M2 `flag.auth.sso` 企业 SSO（后台员工）

## 1.24 范围控制建议（重要）

"全量拉满"在代码上是可行的，在时间上不可行。落地时按这条线切：

- **首版只做 M0**（约 130 项），能支撑"开店、卖货、收款、发货、售后、结算"。
- **第二个迭代做 M1**（约 90 项），补齐营销爆发力、渠道（H5/小程序）、供应链、数据。
- **M2（约 50 项）**按开关灰度，逐项上线，不做整体交付。

未实现的 M1/M2 条目，在 `feature_flag` 表里必须存在且默认关闭，API 返回 `FEATURE_DISABLED`，不要留下"半成品入口"。
