## 6.3 关键骨架（照此实现，别另起风格）

### 6.3.1 状态机

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum OrderStatus { Created, PendingPay, Paid, PartiallyShipped, Shipped, Received, Completed, AfterSale, Cancelled, Closed }

#[derive(Debug, Clone, Copy)]
pub enum OrderAction { ReserveOk, PaySuccess, ShipAll, ShipPart, ReceiveAll, Complete, ApplyAfterSale, AfterSaleDone, Cancel, Timeout, ForceClose }

impl OrderStatus {
    pub fn transition(self, action: OrderAction) -> Result<OrderStatus, DomainError> {
        use OrderStatus::*;
        use OrderAction::*;
        match (self, action) {
            (Created, ReserveOk)          => Ok(PendingPay),
            (PendingPay, PaySuccess)      => Ok(Paid),
            (PendingPay, Cancel) | (PendingPay, Timeout) => Ok(Cancelled),
            (Paid, ShipAll)               => Ok(Shipped),
            (Paid, ShipPart)              => Ok(PartiallyShipped),
            (Shipped, ReceiveAll) | (PartiallyShipped, ReceiveAll) => Ok(Received),
            (Received, Complete)          => Ok(Completed),
            (Paid, ApplyAfterSale) | (Shipped, ApplyAfterSale) | (Received, ApplyAfterSale) => Ok(AfterSale),
            (AfterSale, AfterSaleDone)    => Ok(Completed),
            (s, ForceClose) if !s.is_terminal() => Ok(Closed),
            (s, a) => Err(DomainError::InvalidTransition { from: s.name(), action: a.name() }),
        }
    }
    pub fn is_terminal(self) -> bool { matches!(self, Completed | Cancelled | Closed) }
}
```

要求：`is_terminal` 与迁移表同源；每个 `(status, action)` 组合都有单测，包括全部非法组合。

### 6.3.2 价格引擎签名（纯函数）

```rust
pub struct PriceInput<'a> {
    pub user: &'a UserContext,          // 等级、券包、积分余额
    pub items: &'a [PriceItem],         // sku、单价、数量、类目、店铺
    pub promotions: &'a [PromotionRule],
    pub coupons: &'a [CouponCandidate],
    pub address: &'a AddressContext,    // 省市区、运费模板输入

}
pub struct PriceOutput {
    pub items: Vec<ItemPrice>,           // 每项：原价/活动优惠/券分摊/实付分摊
    pub coupon_used: Vec<CouponApplied>,
    pub points_used: PointsUse,
    pub freight_amount: Decimal,
    pub tax_amount: Decimal,
    pub payable_amount: Decimal,
    pub warnings: Vec<PriceWarning>,
```

**性质测试**（proptest）：`Σ item.payable = payable_amount`；任意优惠组合下 `分摊和 = 优惠总额`；同输入两次结果一致。

### 6.3.3 库存扣减（条件更新，禁止先查后改）

```rust
// 单条预占
let affected = sqlx::query(
  "UPDATE sku_stock SET available_qty = available_qty - $1, locked_qty = locked_qty + $1, version = version + 1
   WHERE sku_id = $2 AND warehouse_id = $3 AND available_qty >= $1 AND deleted_at IS NULL"
).bind(qty).bind(sku).bind(wh).execute(&mut *tx).await?.rows_affected();
if affected == 0 { return Err(StockError::Insufficient { sku, wh, qty }); }
```

批量预占：按 `(warehouse_id, sku_id)` 排序后逐条执行，避免交叉等待；整单失败则逐条回补。

### 6.3.4 幂等中间件

```rust
// 顺序：认证 → 限流 → 幂等 → trace → 业务
pub async fn idempotency(req: Request, next: Next) -> Result<Response, ApiError> {
    let Some(key) = req.headers().get("Idempotency-Key") else { return Ok(next.run(req).await) };
    let scope = format!("{}:{}", req.method(), req.uri().path());
    let fp = fingerprint(&req).await?;                 // body hash
    match store.try_begin(&scope, key, &fp).await? {   // INSERT ON CONFLICT
        Begin::Replay(resp) => return Ok(with_header(resp, "Idempotent-Replayed", "true")),
        Begin::Conflict     => return Err(ApiError::IdempotencyKeyConflict),
        Begin::Fresh(stamp) => {
            let resp = next.run(req).await;
            store.finish(stamp, &resp).await?;
            Ok(resp)
        }
    }
}
```

### 6.3.5 outbox 写入（同事务）

```rust
pub async fn emit(tx: &mut Transaction<'_, Postgres>, ev: DomainEvent) -> Result<(), AppError> {
    sqlx::query("INSERT INTO outbox_event (event_id, aggregate_type, aggregate_id, event_type, payload)
                 VALUES ($1,$2,$3,$4,$5) ON CONFLICT (event_id) DO NOTHING")
      .bind(ev.id).bind(ev.aggregate_type).bind(ev.aggregate_id).bind(ev.event_type)
      .bind(sqlx::types::Json(ev.payload)).execute(&mut **tx).await?;
    Ok(())
}
```

消费者：`SELECT ... WHERE status='pending' AND next_retry_at <= now() ORDER BY created_at LIMIT 100`；成功后置 `sent`；失败 `retry_count += 1`、指数退避；超 8 次置 `dead` 并告警。

### 6.3.6 中间件顺序（固定，不许随意调整）

```
RequestId → Trace/OTel → CORS → Compression → BodyLimit(2MB) → Timeout(30s)
→ RateLimit → Auth(JWT) → RBAC/DataScope → Idempotency → Handler
→ ApiError 映射 → Metrics
```

注意：`Idempotency` 必须在认证之后（要用用户维度 scope）；`payments/callback/{channel}` 单独一条无认证路由，验签在 handler 内完成。

## 6.7 提交与分支规范

- 分支：`feat/P{阶段}-ST-{编号}-{短描述}`，如 `feat/P6-ST-6.3-refund-idempotency`。
- 提交信息：`feat(P6/ST-6.3): 退款单状态机与幂等入账`；`fix(...)`、`refactor(...)`、`chore(...)`。
- 一个 PR 一个 ST；PR 描述必须含 Spec 链接、Gate 证据、遗留项。
- 合并前 CI 全绿（见 05 §5.3），并至少一次人工 review（重点看金额、并发、权限、AI 边界）。
