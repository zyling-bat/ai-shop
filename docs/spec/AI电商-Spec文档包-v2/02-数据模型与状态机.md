# 02 · 数据模型与状态机

> 这是契约文档。表名、列名、约束一经确认，后续 ST 只能追加迁移，不能改名改语义。
> 字段级只对"核心 20 张表"给出，其余给表名 + 必备约束 + 索引要点，细节在各 ST 的 `specs/` 里展开。

---

## 2.0 命名与通用字段

- 表名：小写下划线、单数（`order`、`sku_stock`）；连接表用 `角色_角色`（`role_permission`）。
- 列名：金额 `*_amount`、时间 `*_at`、布尔 `is_* / has_*`、状态 `status`、数量 `*_qty`、比率 `*_rate`。
- 通用列（每张业务表必备）：`id UUID PK`、`created_at TIMESTAMPTZ`、`updated_at TIMESTAMPTZ`、`deleted_at TIMESTAMPTZ NULL`。
- 主键 `UUIDv7`；对外短码用 `short_code`（Base62，独立唯一索引）。
- 状态列 `VARCHAR(32)` + 应用枚举 + CHECK 约束（枚举值列全）。
- 金额 `NUMERIC(20,4)`；比率 `NUMERIC(10,6)`；币种 `currency CHAR(3)` 默认 `CNY`。
- 金额快照与大对象用 `JSONB`（快照必须不可变，仅追加）。

**通用约束**：
1. 所有唯一索引必须显式命名 `uq_<table>_<cols>`，普通索引 `ix_<table>_<cols>`。
2. 软删表上的唯一索引必须带 `WHERE deleted_at IS NULL`（部分唯一索引），否则冲突。
3. 跨域外键不建物理 FK（避免迁移耦合），改由应用层校验 + 定期一致性巡检任务。

## 2.13 状态机全集（12 套）

实现要求：`enum Status` + `fn transition(&self, action: Action) -> Result<Status, InvalidTransition>`，迁移表集中定义 + 单测覆盖全部合法迁移与全部非法迁移。

### ① 订单

| from | action | to | 副作用 |
|---|---|---|---|
| created | reserve_ok | pending_pay | 库存预占、发催付定时任务 |
| pending_pay | pay_success | paid | 库存转占用、发订单已支付事件、通知商家 |
| pending_pay | cancel / timeout | cancelled | 释库存、退券、退款（若已付） |
| paid | ship_all | shipped | 生成包裹与运单、发订阅 |
| paid | ship_part | partially_shipped | 部分包裹 |
| shipped/partially_shipped | receive_all | received | 停自动收货任务 |
| received | auto_complete / confirm | completed | 结算入待结算、开放评价 |
| paid/shipped/received | apply_after_sale | after_sale | 建售后单，订单挂起结算 |
| after_sale | after_sale_done | 回原状态或 completed | 依售后结果 |
| any(非终态) | force_close | closed | 运营关单，全额退款 |

### ② 支付单
`initiated → paying → success | failed | closed`；`success → refunded(partial) | refunded(full)`。约束：`success` 不可回退；重复回调只更新 `callback_count`。

### ③ 退款单
`applied → approved → processing → success | failed`，`applied → rejected`；`failed → processing`（重试，≤3 次）。约束：`success` 终态；金额 ≤ 可退金额（已退 + 本次 ≤ 实付）。

### ④ 售后单
`applied → merchant_review → (approved | rejected)`；`approved → goods_returning → received → refunding → completed`；`rejected → user_appeal → arbitration → (overturn | uphold)`；任一阶段 `closed`（用户撤销）。SLA 超时自动同意（可配开关）。

### ⑤ 结算单
`generated → merchant_confirming → confirmed → payable → paying → paid → closed`；`confirming → disputed → re_generated`。约束：同一 `(merchant_id, period)` 仅一张有效结算单。

### ⑥ 分账指令
`created → submitted → processing → success | partial_success | failed`；`failed → retrying → ...`（≤5 次）→ `manual`。约束：成功金额之和 + 失败金额 = 指令总额。

### ⑦ 审核单（商品/商家/内容）
`submitted → machine_reviewing → human_reviewing → approved | rejected | need_supplement`；`need_supplement → submitted`（计轮次）。

### ⑧ 采购单
`draft → approving → approved → ordered → partially_received → received → settled → closed`；`approved → cancelled`。

### ⑨ 调拨单
`created → approved → outbound → in_transit → inbound → completed`；`any → cancelled`（出库前）。

### ⑩ 盘点单
`created → counting → submitted → reviewed → adjusted → closed`；差异必须走 `adjust` 生成 `stock_log`。

### ⑪ 优惠券
`issued → unused → locked → used`；`unused → expired`；`unused/locked → void`（活动取消）。

### ⑫ 会员订阅
`pending → active → past_due → cancelled | expired`；`past_due → active`（补扣成功）；退订在周期末生效。

## 2.14 幂等、事件、锁

**`idempotency_record`**：`scope VARCHAR(64)`、`key VARCHAR(128)`、`request_hash CHAR(64)`、`status`(processing/done/failed)、`response JSONB`、`expires_at`；唯一 `(scope, key)`；`processing` 超过 60s 视为可重试。

**`outbox_event`**：`event_id UUID` 唯一、`aggregate_type`、`aggregate_id`、`event_type`、`payload JSONB`、`status`(pending/sent/failed/dead)、`retry_count`、`next_retry_at`、`sent_at`；索引 `(status, next_retry_at)`。

**锁**：Redis `SET key val NX PX ttl`，`val = {instance_id}:{trace_id}`，释放走 Lua 比对；键规范 `lock:{biz}:{id}`。

## 2.15 索引、分区与容量

- 高频查询必建复合索引：`order(user_id, status, created_at DESC)`、`order(merchant_id, status, created_at DESC)`、`order(pay_expire_at) WHERE status='pending_pay'`。
- 分区表：`stock_log`、`order_status_log`、`event_log`、`ai_call_log`、`fund_flow`、`audit_log`（按月，保留 12–24 个月，冷数据归档）。
- 大字段（`JSONB` 快照）独立表，避免拖慢主表扫描。
- 预估容量：单日 1 万单 ≈ `order` 年增 365 万行，全部在 PG 单库可承受；超过日 20 万单再考虑按 `merchant_id` 分片（M2）。

## 2.16 种子与迁移纪律

- 迁移文件 `0001_init.sql` 起顺序编号，一文件一主题，禁止一个文件改多域。
- 每批迁移必须能在空库 `up` 全绿、`down` 干净回滚。
- 种子脚本幂等（`ON CONFLICT DO NOTHING/UPDATE`），覆盖：地区字典、类目树、属性模板、测试商家/店铺、示例商品 20 个、测试账号 5 个、运力公司、税率配置、feature_flag 全量默认值。
- 每次迁移后跑一致性巡检：`Σ order_item.amount = order.goods_amount`、`Σ 分账金额 = 指令总额`、`Σ 结算明细 = 结算单金额`。
