# 05 · 验收用例与 Gate

> Gate 不是"看一眼觉得没问题"，而是**可执行的断言**。每条 Gate 必须能用命令、SQL 或测试用例证明；证据写进 `docs/gates/Px.md`。
> 阶段编号：P0–P17（与 07 排期表一致）。

---

## 5.1 阶段 Gate 表

### P0 工程基座
1. `docker compose up -d` 后 `cargo run` 起服务，`GET /healthz` 200、`/readyz` 检查 DB+Redis 均 ok。
2. `cargo fmt --check` 与 `cargo clippy --all-targets -- -D warnings` 零输出。
3. `sqlx migrate run` 在空库成功，`sqlx migrate revert` 可回到空库。
4. `/metrics` 返回 `http_requests_total` 与 `http_request_duration_seconds`。
5. 一次请求能串起 `trace_id`：网关日志 → 服务日志 → DB 审计。
6. ADR-001~008 齐备（分层、DB/ORM、缓存锁、事务消息、AI 网关、前端、渠道、可观测）。

### P1 数据建模
1. 空库跑全量迁移成功；每批可独立回滚。
2. 用 SQL 断言关键约束存在：订单号/支付单号/渠道流水/结算明细唯一索引、`sku_stock` 三个 CHECK、幂等表 `(scope,key)` 唯一。
3. 种子可重复执行两次结果一致（无重复行、无报错）。
4. 每套状态机有单测：合法迁移全过 + 非法迁移全部返回错误（用例数 = 迁移数 × 非法组合）。
5. `scripts/consistency_check.sql` 在种子数据上跑出 0 差异。

### P2 身份与权限
1. 越权矩阵用例全绿：普通用户调后台接口 403；A 商家读 B 商家订单 403；员工无对应权限 403。
2. 同账号 5 次密码错误触发锁定；锁定期内正确密码也拒绝。
3. refresh 轮换后旧 refresh 立即失效（再用返回 401）。
4. 注销流程走完，用户数据按留存策略处理，且不能再登录。
5. 日志抽查 20 条，无完整手机号/证件号明文。

### P3 商品
1. 商品提交审核 → 机审/人审 → 上架 → 下架 → 违规下架，状态日志完整。
2. 属性模板必填校验生效：缺必填属性无法提交审核。
3. 价格六种类型各自生效，且价格展示接口返回的计算结果与引擎一致。
4. 定时上下架到点生效（用秒级可配间隔验证）。
5. 商品变更留版本，历史订单读取快照解释，不随商品改价而变。

### P4 多仓库存与供应链
1. 1000 并发抢 100 库存：成功恰 100，无负库存，`stock_log` 与 `sku_stock` 对账一致。
2. 预占 → 支付占用 → 取消释放，三段数量守恒：`available + locked + occupied` 恒定。
3. 跨仓扣减不死锁（并发用例 200 线程混仓下单通过）。
4. 采购单全流程（审批→到货→入库）后，成本按移动加权平均正确计算，误差 0。
5. 调拨在途：出库后源仓减、目标仓未增，入库后目标仓增；全程可追溯。
6. 盘点差异必须生成调整流水，不允许直接改 `sku_stock`。

### P5 交易核心
1. 黄金链路：加购 → 试算 → 下单 → 支付 → 发货 → 收货 → 评价 → 部分退款 → 完成，全绿。
2. 同一 `Idempotency-Key` 重复提交 10 次，只生成 1 个订单。
3. 客户端试算金额与服务端不一致时返回 `PRICE_CHANGED`，不静默下单。
4. 优惠分摊：`Σ 各项分摊 = 总优惠`，末位差额归最大项（用例 ≥20 条，含 0 元订单、免单、跨店满减）。
5. 多券最优解：给定券包选出的组合使应付最小（穷举对照用例 ≥15 条）。
6. 超时关单任务重跑 3 次，只释放一次库存、只退一次券。

### P6 支付与退款对账
1. 同一回调重放 10 次：入账 1 次，`callback_count` 累加。
2. 回调金额与订单不符 → 拒绝入账并告警（用例覆盖多于/少于两种）。
3. 部分退款两次累计超过实付 → 第二次返回 `REFUND_AMOUNT_EXCEEDED`。
4. 退款按快照比例回冲：3 件商品退 1 件，退款额与分摊一致（误差 0.00）。
5. 对账：构造 `missing_local / missing_channel / amount_mismatch` 三类差异，均能被识别并进入处理流。
6. 支付渠道超时 → 主动查询补偿能纠正最终状态。

### P7 履约与售后
1. 一单多包裹、多运单，轨迹按包裹聚合正确。
2. 重复发货请求（同订单同序号）被唯一约束拦截。
3. 售后：仅退款、退货退款、换货、补发各跑通一条；SLA 超时自动同意（开关打开时）。
4. 售后完成 → 订单结算挂起解除 → 退款金额进入结算冲减。
5. 价保：下单后降价，申请价保补差金额 = 原价 − 现价（含券后口径一致）。

### P8 营销与分销
1. 优惠规则用例 ≥30 条全过：互斥、叠加、优先级、跨店、店铺券与平台券分摊。
2. 活动预算耗尽自动熔断，继续下单不再享优惠且给出提示。
3. 秒杀：库存 100、并发 5000，成功 100，无超卖，DB QPS 不被打满（走 Redis 预热）。
4. 同一用户并发领券不超发（`per_user_limit` 生效）。
5. 分销归因：末次点击优先，归因窗口外不计佣；退款后佣金冻结转冲减。
6. 分销层级深度强制 ≤2，构造三级数据被拒绝。

### P9 多商家结算与财务
1. 跨店订单正确拆单，各店独立履约、独立售后、独立结算。
2. 分账：一笔订单生成分账指令，`Σ 分账 = 订单实付`；分账失败进入重试并最终转人工。
3. 结算单生成：`net = gross − commission − refund_offset + adjust`，误差 0；同一 `(商家, 账期)` 只有一张有效单。
4. 重复生成结算单被唯一约束拦截。
5. 月度关账后，账期内凭证不可修改（数据库层拒绝或应用层拒绝并审计）。
6. 佣金发票与商家进项发票登记闭环；红冲后原票状态正确。
7. 资金流水与支付/退款/分账逐笔对应（`flow_no` 与 `biz_no` 双向可查）。

### P10 内容 · 直播 · 客服
1. 内容机审拦截 → 人审 → 发布；被拒内容不出现在列表与搜索。
2. 内容挂商品：点击进入商品详情并带归因参数。
3. 客服会话：机器人优先 → 未解决 → 转人工，转接摘要含订单号与诉求。
4. 客服工具调用只能读，不能提交售后（用测试证伪）。
5. 直播（若开）：进入直播间 → 挂载商品 → 下单 → 订单打直播归因标签。

### P11 AI 网关
1. 切换主模型只改 `sys_config`，跑通同一组用例，业务代码 diff 为 0。
2. 主 provider 人为置为故障 → 自动降级到备选，响应带 `degraded: true`，总延迟 ≤8s。
3. 非法 JSON 输出触发重试（日志可见 2 次），超限返回 `AI_STRUCTURED_OUTPUT_FAILED` 且业务走兜底。
4. 配额用尽返回 `AI_QUOTA_EXCEEDED`，不影响下单主链路。
5. `ai_call_log` 每条含 tokens、cost、latency、trace_id；成本汇总与手工核算一致。
6. SSE：客户端中途断开，上游请求被取消（日志可见 cancel），无资源泄漏。

### P12 RAG
1. 评测集 50 条：命中率 ≥85%、拒答 100%、引用正确率 ≥90%。
2. 商品下架 5 分钟内，相关 chunk 不再被召回（用例：下架后立刻查询）。
3. 规则类提问只引用"平台规则"文档，不引用商品详情。
4. 无依据时输出"未查到"，不得编造（10 条拒答用例全过）。
5. 增量更新：修改一个文档，10 分钟内检索生效。

### P13 AI 能力落地
1. 18 项能力中已上线的每项有 `evals/` 目录、基线分数、降级说明（未上线的开关默认关闭）。
2. 导购：能收敛预算与品类，输出 3–5 个候选且每个带理由；不得直接改购物车（只能给动作）。
3. 客服：查订单/物流走了工具调用，答复含引用；超范围问题转人工。
4. 售后定损：只输出建议与置信度，无任何自动通过/退款调用（单测证伪）。
5. 运营 NL2SQL：越权表被拒、`LIMIT` 生效、超时中断、SQL 与结果入审计。
6. 内容安全：构造违规输入 20 条，全部被拦截或改写，0 直出。

### P14 前端（Web / H5 / 小程序 / App / 后台）
1. 五个端主流程均可点通（商城：浏览→加购→下单→支付；后台：审核→发货→结算）。
2. 接口层 100% 由 `openapi.json` 生成；仓库内 `grep` 无手写 `fetch(` 业务调用。
3. 每页四态齐全（加载/空/错误/无权限），抽查 10 页。
4. 首页首屏 P95 ≤1.5s（4G 模拟）；商品详情可交互 ≤1.2s。
5. 小程序：微信登录、支付、订阅消息、分享卡片跑通（真机）。
6. App：扫码、推送、原生支付 SDK 跑通（真机）。
7. 无障碍基础项：键盘可达、对比度、图片 alt（自动扫描 0 严重项）。

### P15 数据与风控
1. 埋点事件模型落地：曝光/点击/加购/下单/支付/退款 6 类事件可查，字段完整率 ≥99%。
2. 指标口径字典存在且代码取值与文档一致（GMV 含税/不含税两个口径都能出数）。
3. 漏斗看板与明细表可对上（抽样 3 天，误差 ≤1%）。
4. AB 实验：分流稳定（同用户多次命中原组）、指标可计算。
5. 风控：构造刷单/羊毛党/骗赔样本各 20 条，命中率 ≥85%，正常用户误杀 ≤1%。
6. 券滥用：同设备 5 账号批量领券被识别并限制。

### P16 质量 · 性能 · 安全
1. 压测：下单 P95 ≤300ms，商品详情 P95 ≤120ms，搜索 P95 ≤150ms，AI 首 token ≤1.5s。
2. 24 小时稳定性：无内存增长趋势（RSS 波动 ≤10%），无连接泄漏。
3. OWASP 自检 0 高危：注入、越权、XSS、SSRF、文件上传、敏感信息泄露逐项有结论。
4. 依赖审计 `cargo deny` 无高危漏洞；镜像无高危 CVE。
5. 限流分级生效：单接口、单用户、全站三层阈值分别可触发。
6. 告警演练：DB 连接池耗尽、支付回调失败率升高、AI 降级率升高，三条告警均能在 1 分钟内触发。

### P17 部署上线
1. 预发环境一键部署成功，`/readyz` 全绿。
2. 回滚演练 ≤5 分钟完成，回滚后核心链路自检通过。
3. 密钥不落镜像（镜像层扫描无 secret）、不落日志（抽查）。
4. 备份恢复演练：从备份恢复至新库，数据一致性校验通过，RTO ≤30min。
5. 灰度：按 5% → 20% → 100% 放量，各阶段错误率与延迟无异常。

## 5.2 关键用例库（Given-When-Then，可直接转测试）

**T-01 不超卖**
Given SKU A 库存 100，1000 个用户并发下单各 1 件
When 并发提交
Then 成功订单 100 个，`sku_stock.available = 0`，无负值，失败请求返回 `STOCK_INSUFFICIENT`

**T-02 幂等下单**
Given 同一用户、同一 `Idempotency-Key`
When 连续提交 10 次相同订单请求
Then 只生成 1 个订单，其余 9 次返回首次结果并带 `Idempotent-Replayed`

**T-03 回调幂等**
Given 支付单已成功
When 同一渠道流水号回调重放 10 次
Then 订单 `paid_amount` 只增一次，`callback_count = 10`，无重复流水

**T-04 金额分摊**
Given 订单含 SKU X(100 元)、Y(200 元)、Z(300 元)，平台满减 60 元
When 计算价格
Then 分摊为 -10/-20/-30，`Σ = -60`，应付 540.00

**T-05 末位差额**
Given 三件商品各 33.33 元，优惠 100 元
When 按比例分摊
Then 分摊为 33.33/33.33/33.34（或等价规则），`Σ = 100.00`，误差 0

**T-06 部分退款回冲**
Given 订单 3 件共 300 元，优惠 30 元，实付 270 元
When 退 1 件
Then 退款 90.00 元，剩余可退 180.00 元

**T-07 券互斥**
Given 用户持有平台券 A（满 200-20）与品类券 B（满 200-30），规则为互斥
When 结算
Then 自动选 B，提示"A 与 B 不可同用"

**T-08 状态机非法迁移**
Given 订单状态 `completed`
When 调用 `POST /orders/{no}:cancel`
Then 返回 `ORDER_STATE_INVALID`，状态不变，产生告警

**T-09 数据权限**
Given 商家 M1 的员工账号，订单属于 M2
When 查询该订单
Then 返回 403 `DATA_SCOPE_DENIED`，且审计留痕

**T-10 价格变化**
Given 客户端试算 199 元，服务端结算 219 元
When 下单
Then 返回 `PRICE_CHANGED` 与差异说明，不创建订单

**T-11 超时关单重入**
Given 订单待支付已超时
When 关单任务连续执行 3 次
Then 只释放一次库存、只退一次券，状态仅迁移一次

**T-12 跨店拆单结算**
Given 一单含 M1、M2 两家商品
When 支付成功
Then 生成 2 个履约单、2 条结算明细、2 条分账收款方；`Σ 分账 = 实付`

**T-13 分账失败重试**
Given 分账指令提交后渠道返回失败
When 重试 5 次仍失败
Then 状态转 `manual`，生成工单，不重复打款

**T-14 结算重复拦截**
Given 账期内已生成结算单
When 再次触发生成
Then 返回 `SETTLEMENT_DUPLICATE`，不产生第二张单

**T-15 AI 不越权**
Given 导购 Agent 判断用户想买 X
When 生成回复
Then 只能输出加购动作卡片，不直接写 `cart_item`（代码审查 + 单测证伪）

**T-16 AI 降级**
Given 主模型超时
When 用户发起导购对话
Then 8s 内返回降级结果（筛选式推荐），`degraded=true`，主链路不受影响

**T-17 RAG 拒答**
Given 知识库没有"是否支持货到付款"的依据
When 用户提问
Then 回答"未查到相关规则，建议咨询人工"，不编造，引用为空

**T-18 内容安全**
Given AI 生成文案含绝对化用语
When 过内容安全
Then 被拦截或改写，用户端不出现原文

**T-19 渠道归因**
Given 用户从小程序分享卡片进入
When 下单
Then 订单 `channel=miniapp`、`source` 含 `scene` 与分享人标识

**T-20 越界重构**
Given 本 ST 只允许改 6 个文件
When 提交 PR
Then `git diff --stat` 显示改动文件 = 6，超出即 CI 失败

## 5.3 CI 必跑清单

```
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo test --workspace
cargo sqlx prepare --check          # 离线元数据与代码一致
cargo xtask openapi --check         # 契约与实现 diff 为零
cargo deny check                    # 依赖与许可证
cargo xtask consistency --check     # 金额/库存/结算一致性断言
cargo xtask eval --smoke            # AI 冒烟评测（分数不下降）
```

**CI 全绿是提交的前提**，不是"事后再补"。
