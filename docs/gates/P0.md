### 5. 分层校验（C3）

### 6. 反向自证（越界可被发现）

操作：临时在 `crates/domain/Cargo.toml` 加入 `axum.workspace = true`，执行：

```
$ cargo tree -p domain --edges normal
domain v0.1.0 (C:\Users\admin\Documents\电商系统\crates\domain)
└── axum v0.8.9
    ├── axum-core v0.5.6
    ├── axum-macros v0.5.1 (proc-macro)
```

结论：越界依赖在 `cargo tree` 中**立即可见**，ADR-001 白名单可作为评审依据。

随后立即删除该行，复验结果：

```
$ cargo tree -p domain --edges normal
domain v0.1.0 (C:\Users\admin\Documents\电商系统\crates\domain)

$ cargo fmt --check        # 无输出，退出码 0
$ cargo clippy --all-targets -- -D warnings   # 无告警，退出码 0
```

`Cargo.lock` 中 `domain` 条目已恢复为无 `dependencies` 列表，仓库无残留改动。

## 三、环境限制说明

本机**没有 docker，也没有 psql**（已实测）。因此：

- P0-1 的 "`docker compose up -d` + `/readyz` 检查 DB+Redis" 与 P0-3 的 "`sqlx migrate run` / `revert`" **无法在本机完整验证**，需等 ST-0.3 确定运行环境（Docker Desktop / 本地 PostgreSQL 17 + Redis 7 / 远程开发库）后补齐。
- 在 ST-0.3 完成前，`/readyz` 保持 404，不返回假的 200 通过。
