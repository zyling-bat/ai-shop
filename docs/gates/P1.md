## 二、ST-1.1 实测证据

环境：Windows + PowerShell 5；PostgreSQL 17.6（`C:\Users\admin\dev\pgsql`，按 `docs/gates/P0.md` §五 手动启动）；`sqlx-cli 0.9.1`。

### 1. 空库全量 up / 独立 down / 再 up

新建空库 `ecom_p1_verify` 后执行（`DATABASE_URL` 指向该库）：

```text
sqlx migrate run
Applied 20261124143103/migrate audit log (7.9146ms)
Applied 20261125103000/migrate idempotency record (10.0368ms)
Applied 20261125103100/migrate outbox event (7.7829ms)

to_regclass 查询 → audit_log | idempotency_record | outbox_event
```

回滚（验证可独立回滚，不连带其他表）：

```text
sqlx migrate revert
Applied 20261125103100/revert outbox event (10.6708ms)
→ idempotency_record | NULL          （outbox_event 已删，幂等表仍在）

sqlx migrate revert
Applied 20261125103000/revert idempotency record (6.2953ms)
→ NULL | NULL                        （两表均已删，audit_log 未受影响）

sqlx migrate run
Applied 20261125103000/migrate idempotency record (14.6028ms)
Applied 20261125103100/migrate outbox event (10.3093ms)
→ idempotency_record | outbox_event
```

### 2. 约束断言脚本（两次执行一致）

```text
psql -v ON_ERROR_STOP=1 -f scripts/verify_p1_constraints.sql
NOTICE:  P1 ST-1.1 约束断言全部通过
exit=0

（重复第二次）
NOTICE:  P1 ST-1.1 约束断言全部通过
exit=0
```

脚本断言的实际事实：

- `idempotency_record`、`outbox_event` 存在
- `uq_idempotency_record_scope_key` 为唯一索引且带 `WHERE deleted_at IS NULL`
- `uq_outbox_event_event_id` 为唯一索引且带软删条件
- `ix_outbox_event_status_next_retry_at` 列为 `(status, next_retry_at)`
- `ck_idempotency_record_status`、`ck_outbox_event_status`、`ck_outbox_event_retry_count` 存在
- 非法 `status` 与负 `retry_count` 写入均被 CHECK 拒绝（子事务回滚，无残留数据）

## 三、边界说明

- 本机无 Docker（P0 已记录），迁移验证使用本机原生 PostgreSQL 17.6，不声称 `docker compose up -d` 已实测。
- CI 当前只运行 fmt / clippy / test，**不执行数据库迁移**；P1-1/P1-2 依赖本地实测证据，迁移的自动化校验随 TD-006（`.sqlx/`）与数据库 CI 一并偿还。
- `ecom_p1_verify`、`ecom_p1_identity` 均为一次性验证库，不构成部署产物。
- `user` 是 PostgreSQL 保留字，本项目所有涉及该表的 SQL 统一写作 `"user"`；`NULLS NOT DISTINCT` 依赖 PG15+，本项目基线为 PG17。
